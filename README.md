# sepehr
# پنل مدیریت Xray روی Railway (VLESS / VMess / Trojan over WebSocket)

نسخه‌ای از پنل که مخصوص اجرا روی [Railway](https://railway.app) طراحی شده — بدون نیاز به VPS، بدون نیاز به مدیریت گواهی TLS.

## ⚠️ محدودیت‌های مهم قبل از شروع

1. **رایگان نیست:** Railway فقط ۳۰ روز تِرایال با ۵ دلار اعتبار می‌دهد؛ بعدش باید پلن Hobby (~۵ دلار/ماه) بگیرید.
2. **فقط WebSocket:** چون Railway پورت‌های دلخواه TCP باز نمی‌کند، هر سه پروتکل از طریق WebSocket و پشت TLS خودِ Railway کار می‌کنند (نه TCP خام). این یعنی سرعت/تاخیر ممکن است کمی با نسخه‌ی VPS فرق کند، ولی از نظر عملکردی کاملاً سالم است.
3. **حجم محدود:** پلن Hobby ماهانه سقف مصرف منابع دارد؛ برای مصرف زیاد (چند کاربر پرترافیک) به‌صرفه نیست.
4. **دیتابیس باید روی Volume باشد** وگرنه با هر دیپلوی جدید لیست کاربران پاک می‌شود (پایین توضیح داده شده).

## مراحل دیپلوی

### ۱. آپلود پروژه روی گیت‌هاب
یک ریپوی جدید بسازید و محتوای این پوشه را در آن push کنید (یا از Railway CLI مستقیم دیپلوی کنید).

### ۲. ساخت پروژه در Railway
- در [railway.app](https://railway.app) وارد شوید → **New Project** → **Deploy from GitHub repo**
- ریپوی خودتان را انتخاب کنید. Railway خودش `Dockerfile` را تشخیص می‌دهد و طبق آن بیلد می‌کند.

### ۳. تنظیم متغیرهای محیطی
در تب **Variables** پروژه:
```
JWT_SECRET=یک رشته‌ی تصادفی طولانی
ADMIN_USERNAME=admin
ADMIN_PASSWORD=یک پسورد قوی
DATA_DIR=/app/data
```

### ۴. افزودن Volume دائمی (خیلی مهم)
در تب **Settings** سرویس → بخش **Volumes** → یک Volume جدید بسازید و آن را روی مسیر `/app/data` mount کنید. بدون این کار، با هر دیپلوی جدید همه‌ی کاربرانی که ساخته‌اید پاک می‌شوند.

### ۵. ساخت دامنه‌ی عمومی
در تب **Settings** → بخش **Networking** → **Generate Domain** بزنید. Railway یک دامنه مثل `your-app.up.railway.app` با HTTPS خودکار می‌دهد. (اگر دامنه‌ی اختصاصی دارید، می‌توانید Custom Domain هم اضافه کنید.)

### ۶. وارد کردن دامنه در خود پنل
بعد از بالا آمدن سرویس، وارد داشبورد پنل شوید (`https://your-app.up.railway.app`)، لاگین کنید، و در بخش «تنظیمات سرور» همان دامنه‌ای که Railway داد را وارد و ذخیره کنید. این دامنه در ساخت لینک‌های اتصال کاربران استفاده می‌شود.

## نحوه‌ی کار (خلاصه‌ی فنی)

- یک پروسه‌ی Node.js تک‌پورت (روی `$PORT` که Railway می‌دهد) هم داشبورد پنل و هم پروکسی WebSocket را سرو می‌کند.
- Xray-core به صورت child-process داخل همان کانتینر اجرا می‌شود و فقط روی `127.0.0.1` (سه پورت داخلی جدا برای هر پروتکل) گوش می‌دهد؛ هرگز مستقیم به بیرون اکسپوز نمی‌شود.
- درخواست‌های WebSocket به مسیرهای `/vless-ws`، `/vmess-ws`، `/trojan-ws` توسط Node به پورت داخلی Xray مربوطه فوروارد می‌شوند.
- TLS واقعی (گواهی، تمدید خودکار و غیره) را کلاً خودِ Railway مدیریت می‌کند؛ داخل کانتینر شما هیچ گواهی‌ای لازم نیست.
- با هر افزودن/حذف/ویرایش کاربر، کانفیگ Xray دوباره ساخته و پروسه‌ی Xray ری‌استارت می‌شود.

## استفاده در اپ‌های کلاینت

لینک تولیدشده برای هر کاربر (`vless://…`, `vmess://…`, `trojan://…`) یا لینک سابسکریپشن (`/sub/TOKEN`) را در اپ‌هایی مثل v2rayNG (اندروید)، NekoBox، Streisand (iOS) یا Shadowrocket وارد/ایمپورت کنید. همه‌شان از پروتکل `type=ws` و `security=tls` استفاده می‌کنند.

## ساختار پروژه

```
vpn-panel/
├── Dockerfile # نصب Xray-core + اجرای پنل
├── railway.json # تنظیمات بیلد Railway
├── server.js # نقطه‌ی ورود (تک‌پورت، شامل پروکسی WS)
├── src/
│ ├── db.js # دیتابیس فایلی (روی Volume)
│ ├── auth.js
│ ├── proxy.js # فوروارد WebSocket به Xray داخلی
│ ├── routes/
│ │ ├── auth.js
│ │ ├── clients.js
│ │ └── settings.js
│ ├── xray/
│ │ ├── configBuilder.js # کانفیگ Xray با اینباندهای WS
│ │ └── runner.js # اجرا/ری‌استارت Xray به‌عنوان child process
│ └── utils/
│ ├── id.js
│ └── links.js # ساخت لینک‌های vless/vmess/trojan روی wss
└── public/ # داشبورد وب (HTML/JS ساده)
```

## توسعه‌های پیشنهادی بعدی

- آمار مصرف ترافیک واقعی از طریق Xray Stats API
- محدودسازی خودکار حجم مصرفی هر کاربر
- بکاپ خودکار از `data/db.json` (مثلاً به یک storage خارجی، چون Volume خودِ Railway هم باید جدا بکاپ گرفته شود)
